# 智能哨兵 — 报警工单管理系统

## 产品概述

智能哨兵是一款面向工业监控场景的报警管理工具。系统对接外部报警数据源，将实时报警记录转化为可追踪、可闭环处理的工单，实现从"发现报警"到"确认消警"的完整业务流程。

目标用户：工厂运维人员、值班工程师、设备管理员。

核心流程：报警接入 → 记录浏览 → 工单生成 → 工单处理 → 消警确认 → 历史追溯。

---

## 功能模块

### 1. 报警记录

#### 产品目标
提供一个报警浏览界面，让运维人员查看当前活跃报警，并从中生成工单。已生成工单的报警记录不再显示，避免重复处理。

#### 页面布局
- 顶部：检索条件区
- 中部：报警记录表格 + 分页器
- 操作列：详情、生成工单

#### 检索条件
| 字段 | 类型 | 说明 |
|---|---|---|
| 位号 | 文本输入 | 按报警源位号模糊匹配 |
| 报警描述 | 文本输入 | 按报警描述关键字模糊匹配 |
| 报警时间 | 日期时间区间 | 报警产生时间的起止范围 |

> 所有过滤条件随分页请求提交，由服务端执行过滤。

#### 数据表格
| 列名 | 字段 | 说明 |
|---|---|---|
| 序号 | — | 当前页序号 |
| 位号 | sourceName | 报警源显示名称 |
| 报警描述 | description | 报警详细描述 |
| 报警子类型 | detailSubType | 具体报警分类 |
| 优先级 | priority | 报警级别（如高/中/低） |
| 报警值 | value | 触发报警时的实时数值 |
| 触发条件 | definition.limit | 报警阈值定义 |
| 路径 | sourcePath | 报警源在系统中的路径 |
| 报警时间 | activeTime | 报警激活时间 |
| 操作 | — | 详情、生成工单 |

#### 交互行为

**初始加载**
页面加载后自动拉取第一页报警记录。

**分页**
每页 20 条，支持前后页跳转和页码跳转。

**详情查看**
点击"详情"弹出报警详情面板，展示：位号、源路径、具体类型、报警描述、一级分类、子类型、逻辑分组、优先级、报警触发条件（触发属性、报警值、数字质量）、报警配置、是否已恢复。

**生成工单**
点击"生成工单"后：
1. 系统自动生成工单编码：`AROrder + YYYYMMDD + 4位随机数字`
2. 将该条报警记录的关键信息（位号、描述等）带入新工单
3. 调用接口创建工单记录
4. 跳转至报警工单页面
5. 该报警记录在本页面不再显示（已生成工单的报警自动过滤）

#### 数据源
- 报警记录从外部报警历史接口分页获取
- 前端调用本地代理端点获取数据，避免直接访问外部接口的跨域和安全问题

### 2. 报警工单

#### 产品目标
提供工单的完整生命周期管理：查询、修改、删除、导入、导出，以及工单与历史报警的关联追溯。

#### 页面布局
- 顶部：检索条件区 + 批量操作按钮（导入、导出）
- 中部：工单表格 + 分页器
- 操作列：编辑、删除、查看详情

#### 检索条件
| 字段 | 类型 | 说明 |
|---|---|---|
| 工单编码 | 文本输入 | 按工单编码模糊匹配 |
| 报警位号 | 文本输入 | 按关联报警位号模糊匹配 |
| 工单状态 | 下拉选择 | 全部 / 未处理 / 已确认 |

#### 数据表格
| 列名 | 字段 | 说明 |
|---|---|---|
| 序号 | — | 当前页序号 |
| 工单编码 | orderCode | 系统自动生成的唯一编码 |
| 报警位号 | sourceName | 关联的报警源位号 |
| 报警描述 | description | 报警描述摘要 |
| 工单状态 | status | 未处理 / 已确认 |
| 问题原因 | cause | 填写的问题根因 |
| 纠正预防措施 | measures | 填写的纠正和预防措施 |
| 确认时间 | confirmTime | 状态变更为已确认的时间 |
| 附件 | attachments | 支持点击下载 |
| 备注 | remark | 补充说明 |
| 操作 | — | 编辑、删除、详情 |

#### 工单状态流转
```
未处理 → 已确认
```
- 未处理：工单刚创建或仍在处理中
- 已确认：运维人员确认问题已解决，此时触发消警动作

#### CRUD 操作

**创建工单**
仅通过报警记录页面的"生成工单"入口创建，不在工单页面提供独立创建入口。

**编辑工单（弹窗）**
可修改字段：工单状态、问题原因、纠正预防措施、备注、附件。
- 当状态从"未处理"变更为"已确认"时，自动调用消警接口关闭声光报警
- 确认后记录确认时间

**删除工单**
逻辑删除：标记 delete_flag=1 并记录删除时间，不物理删除数据。
所有查询默认过滤 delete_flag=0 的记录。

**导入（CSV）**
- 按工单编码匹配更新现有记录
- 编码不存在的记录跳过并提示错误
- 提供模板下载功能供用户参考格式

**导出（CSV）**
导出当前检索条件下的完整列表数据。

#### 附件处理
- 支持上传单个文件，最大 5MB
- 文件在前端转为 Base64 存储
- 附件以 JSON 数组格式存储，包含：文件名、大小、MIME 类型、Base64 数据
- 表格中附件列支持点击下载

### 3. 工单详情

#### 页面布局
- 顶部：工单基本信息卡片（含附件列表，支持下载）
- 下方：页签切换区

#### 页签内容

**历史报警**
按该工单关联的位号（sourcePath）查询该位号的所有历史报警记录，帮助运维人员了解该报警点的历史触发情况。

**历史工单**
按该工单关联的位号查询工单表，展示该报警点曾产生的所有工单记录，便于追溯处理历史。

## 数据模型

### AlarmRecord（报警记录）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 报警唯一标识 |
| sourceName | string | 报警源显示名称（位号） |
| sourcePath | string | 报警源路径 |
| description | string | 报警描述 |

| priority | string | 优先级 |
| value | object | 报警值 { value: number } |
| definition | object | 报警定义 { limit?: number } |
| activeTime | datetime | 报警激活时间 |
| inactive | boolean | 是否已恢复 |

### WorkOrder（报警工单）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 工单唯一标识 |
| orderCode | string | 工单编码（AROrder + 日期 + 随机数） |
| sourceName | string | 关联报警位号 |
| sourcePath | string | 关联报警路径 |
| description | string | 报警描述 |
| status | enum | 未处理 / 已确认 |
| cause | text | 问题原因 |
| measures | text | 纠正预防措施 |
| remark | text | 备注 |
| attachments | text | 附件 JSON 数组（Base64） |
| confirmTime | datetime | 确认时间 |
| delete_flag | int | 0=正常, 1=已删除 |
| delete_time | datetime | 删除时间 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

## 接口约定

### 报警记录相关

**获取报警记录列表**
```
POST /api/alarms/history
```
请求体：
```json
{
  "pageNum": 1,
  "pageSize": 20,
  "sortBy": "activeTime",
  "sortOrder": "desc",
  "sourceNameLike": "T-101",
  "keyword": "温度过高",
  "activeTimeBegin": "2024-08-31T00:00:00.000+08:00",
  "activeTimeEnd": "2024-09-01T00:00:00.000+08:00"
}
```
响应：
```json
{
  "success": true,
  "data": [...],
  "total": 192,
  "page": 1,
  "size": 20
}
```

**获取报警详情**
```
GET /api/alarms/:id
```

### 工单相关

**创建工单**
```
POST /api/work-orders
```
请求体：
```json
{
  "orderCode": "AROrder202509081234",
  "sourceName": "T-101",
  "sourcePath": "/plant1/areaA/T-101",
  "description": "温度过高报警",
  "status": "未处理"
}
```

**查询工单列表**
```
GET /api/work-orders?page=1&size=20&orderCode=xxx&sourceName=xxx&status=xxx
```
默认过滤条件：delete_flag = 0

**更新工单**
```
PUT /api/work-orders/:id
```

**删除工单（逻辑删除）**
```
DELETE /api/work-orders/:id
```

**按位号查询历史报警**
```
GET /api/alarms/history?sourcePath=/plant1/areaA/T-101
```

**按位号查询历史工单**
```
GET /api/work-orders?sourcePath=/plant1/areaA/T-101&includeDeleted=false
```

**消警操作**
```
POST /api/alarms/:id/cancel
```
请求体：
```json
{ "status": 0 }
```
在工单状态变更为"已确认"时自动调用。

### 文件相关

**上传附件**
```
POST /api/files/upload
```
支持 multipart/form-data 上传。

**下载附件**
```
GET /api/files/:fileId
```

**导入工单（CSV）**
```
POST /api/work-orders/import
```

**导出工单（CSV）**
```
GET /api/work-orders/export?orderCode=xxx&sourceName=xxx&status=xxx
```

## 关键业务规则

1. **已生成工单的报警不再显示**：报警记录页面自动过滤已关联工单的报警，防止重复派单。
2. **工单确认即消警**：工单状态变更为"已确认"时，系统同步调用消警接口关闭声光报警，实现业务闭环。
3. **逻辑删除**：所有删除操作均为逻辑删除，保留数据可追溯性。
4. **位号关联**：工单详情中的历史报警和历史工单均以 sourcePath（报警路径/位号）作为关联键。
5. **编码唯一**：工单编码生成后不可修改，采用 `AROrder + YYYYMMDD + 4位随机数` 的格式。
